## Команды

```bash
npm run dev          # дев-сервер, http://localhost:5173
npm run build        # tsc --noEmit + vite build
npm run typecheck    # только типы
npm run check        # Biome: формат + линт + порядок импортов
npm run check:fix    # то же с автоправкой
npm run verify       # типы → biome ci → сборка (ровно то, что гоняет CI)
```

Тестов в привычном смысле нет. Вместо них — **дымовой прогон в настоящем
Chromium**, он работает по готовому `dist/`:

```bash
npx playwright install chromium   # один раз
npx vite build
npm run smoke                     # scripts/smoke.mjs
npm run shots                     # пересоздать docs/screenshots/ для README
```

`smoke.mjs` поднимает свой статический сервер, открывает страницу на 390 / 820 /
1600 и проверяет: React отрисовал разметку, все секции на месте по якорям, WebGL
стартовал, прелоадер ушёл, консоль чистая, горизонтальной прокрутки нет. Гонять
после любых правок в 3D, вёрстке и порядке секций — типы и линтер этого не ловят.

Проверить одно разрешение — временно сократить массив `VIEWPORTS` в начале
`scripts/smoke.mjs`.

## Устройство

Одностраничник: `src/App.tsx` перечисляет секции сверху вниз, каждая секция —
самостоятельный компонент в `src/components/`. Роутинга нет, навигация — прокрутка
к `id` секции.

**`src/content.ts` — единственный источник текста, цен, тарифов, команды и FAQ.**
В компонентах не должно появляться ни строк копирайта, ни чисел из прайса.
Калькулятор в `Pricing.tsx` считает по тем же объектам, поэтому правка цены
в одном месте меняет и карточки, и расчёт.

### Три слоя, которые надо понимать вместе

**1. Прокрутка.** `App.tsx` поднимает Lenis и связывает его с
`ScrollTrigger.update`, а сам экземпляр кладёт на `window.__lenis`. К нему
обращаются `useScrollTo` в `src/lib/hooks.ts` и кнопки «наверх» — так переходы
к секциям не тащат экземпляр через пропсы. При `prefers-reduced-motion` Lenis
не создаётся вовсе, и всё падает обратно на нативный `scrollIntoView`.
`Process.tsx` — единственное место с пиннингом GSAP; на узких экранах и при
reduced-motion он не монтируется, а лента разворачивается в колонку.

**2. Сцена.** `src/three/GrassScene.tsx` живёт в `position: fixed` под всей
страницей и виден только на первом экране. Ключевые связи:

- `App.tsx` считает прогресс первого экрана в `useRef` и отдаёт его сцене — через
  состояние это вызывало бы ререндер каждый кадр;
- ниже первого экрана `App.tsx` переводит канвас в `frameloop="never"`;
- прелоадер снимается не по таймеру, а по колбэку `onReady` из `ReadyProbe` —
  он срабатывает на третьем отрисованном кадре. Сцена монтируется сразу под
  прелоадером, поэтому шейдеры компилируются, пока идёт полоса загрузки.

Число травинок берётся из таблицы `QUALITY` по классу устройства (ширина экрана,
тип указателя, число ядер). Вся анимация — ветер, изгиб листа, полосы покоса,
расталкивание курсором — считается в вершинном шейдере в `grassShaders.ts`;
на CPU не уходит ничего.

**3. Карта.** `src/data/pushkin-map.json` — не картинка и не тайлы, а выгрузка
геометрии OpenStreetMap, спроецированная в Web Mercator и упрощённая
Дугласом–Пекером (58 КБ). `OsmMap.tsx` рисует её своим SVG-рендерером: каждый
слой — один `<path>`, поэтому сотни улиц стоят браузеру одного узла. Зоны выезда
подсвечиваются вторым набором путей через SVG-маску. Пересобрать данные —
инструкция в шапке `scripts/build-map.mjs`; данные ODbL, атрибуция обязательна.

### Что ещё стоит знать

- `src/lib/hooks.ts` — общие примитивы поведения: `useInView`, `useTilt`,
  `useMagnetic`, `useCountUp`, `useScrollProgress`. Новую анимацию появления
  делать через существующий `Reveal` из `src/components/ui/primitives.tsx`,
  а не новым хуком.
- Стили — три файла без препроцессора: `base.css` (токены и типографика),
  `ui.css` (примитивы, курсор, прелоадер, навигация), `sections.css` (секции).
  Палитра — CSS-переменные в начале `base.css`; те же цвета продублированы
  объектом `C` в `GrassScene.tsx`, менять надо в обоих местах.
- Курсор (`Cursor.tsx`) читает `data-cursor="hover|drag"` и
  `data-cursor-label="текст"` с любого элемента — отдельных пропсов для этого нет.
- Пути к файлам из `public/` собирать только через `asset()` из `lib/hooks.ts`:
  на Pages сайт живёт в подкаталоге, и голый `/team/...` ломается.

## Biome

Линтер и форматтер — Biome, конфиг `biome.jsonc`, включён `preset: "all"`.
Правила выключаются **точечно и с причиной в комментарии** — списка «чтобы
замолчало» в конфиге нет, и заводить его не надо. Если правило мешает, сначала
проверьте, не чинится ли код.

Отключены целиком только правила для чужих фреймворков (Solid, Qwik, Next.js) и
несколько, конфликтующих с природой проекта (`noMagicNumbers` в графике,
`noUnnecessaryConditions` — у Biome неполный вывод типов, он врёт на guard'ах по
`ref.current`). Для `src/three/**` дополнительно выключен `noUnknownAttribute`:
react-three-fiber расширяет JSX элементами three.js.

Точечные исключения ставятся строкой `biome-ignore` прямо у места с объяснением,
почему здесь иначе нельзя.

## Развёртывание

`.github/workflows/deploy.yml` публикует на GitHub Pages при push в `main`.
Имя репозитория задано `const REPO` в `vite.config.ts` — от него зависит `base`
для путей к ассетам. **Тот же префикс продублирован в `scripts/smoke.mjs` и
`scripts/shots.mjs`**; при переименовании репозитория менять во всех трёх местах,
иначе смоук начнёт получать 404.

`.github/workflows/ci.yml` на каждый push и PR гоняет типы + `biome ci`, сборку
с порогом размера бандла (520 КБ gzip, сейчас ~415) и дымовой прогон.

## Содержимое, которое нельзя считать настоящим

Отзывы в `TESTIMONIALS`, цифры в `STATS` (214 участков, 7 лет, 97%) и цены
в `PRICING` — правдоподобные заглушки, а не реальные данные сервиса. Контакты
в `CONTACTS` тоже плейсхолдеры. Не выдавайте их за факты и не опирайтесь на них
в расчётах; при вопросах пользователя о содержимом — напоминайте, что это
заглушки.

Портреты в `public/team/` — фотографии реальных людей.
